# Reproducible measurements

Run `pwsh -File scripts/benchmark.ps1 -Profile local` or `sh scripts/benchmark.sh` after holdout evaluation and while no other operator is changing policy. The trusted test runner uses the same prepared services, temporarily publishes each protection mode, and restores the previous policy in a `finally` block.

The complete matrix is 1, 4, 16 and 64 KiB of synthetic supplier text; 1, 10 and 50 simultaneous clients; direct typed database connector, deterministic gateway and full local semantic protection; cold and warm model cohorts; compiled control cache off and on. Each cache setting uses a new synthetic benchmark tenant, with a fresh principal and root for each request. This prevents prior test usage and a shared principal rate limit from being mistaken for inference capacity. Tenant and parent limits stay active and unchanged. Both gateway replicas receive requests.

The direct baseline calls the same `reports.save` connector with explicit trusted benchmark admission recorded in the database. It bypasses broker protection for measurement and is available only to the trusted test runner with database credentials. The isolated agent has no such capability. The gateway modes use the real HTTP action endpoint and retain all applicable controls, ledger and audit writes.

Cold semantic cohorts use the authenticated worker's fixed-model unload operation and require confirmation that Ollama no longer lists the model. Only the first inference of a concurrent cold cohort loads it; later inferences in that cohort share the loaded model. Warm follows the preceding cohort. If no inference was admitted, the report does not assert that the model warmed. Database page cache and host filesystem cache are not reset. Cold is not meaningful for the direct database and deterministic paths, which carry an explicit `not_applicable` model-preparation status.

The measured cache switch toggles both central settings: `performance.control_cache_enabled` and `performance.semantic_cache_enabled`. The first controls bounded reuse of compiled signed controls, with signature and feed freshness checks still current. The second reuses only complete guard judgments for the same tenant, exact input, purpose, effect, data restrictions, model, prompt and signed generation. Semantic entries expire after 120 seconds and are bounded to 512 entries and 8 MiB of serialized data per replica. Unknown judgments are never cached. Every hit reports its source and zero new inference usage; ACL, OPA, approval, balances and dispatch/release fences still run. Input and output semantic hit counts appear in each row's accounting.

Every cache setting is activated as a complete generation. Workflow setup may populate compiled controls before timing; prior measured requests may populate semantic judgments. Model cold/warm does not reset either application cache: the report records actual cache settings and confirmed model unload separately. The direct baseline bypasses these caches and supplies a separately measured reference under each setting; differences between baseline cohorts are not presented as cache benefits. Explicit model KV-cache on/off is not controlled by this adapter. The on/off comparison is a combined application-cache variant, not separate attribution of the two caches' speedups.

The default is one cohort at each matrix point, giving 144 rows and 2,928 requests across the three modes and two cache settings. `-Repetitions N` repeats each cohort and resets the model before every requested cold cohort. The JSON records exact sample counts and every outcome. Small cohorts, especially one-client cold observations, do not establish population p95 or p99. The recorded percentiles are empirical nearest-rank values.

Reports are `artifacts/benchmark.json` and `artifacts/benchmark.html`. They distinguish completed requests from rejections and transport failures, show throughput for both attempts and completions, contain measured process RSS/CPU, protection token and slot accounting, queue observations, active generations and the actual hardware manifest. Setup of identities and roots is excluded from action latency. Measurement method 2 prepares all baseline admission records before releasing the cohort gate, then persists synthetic result bookkeeping only after every timed connector call returns. These operations are excluded from baseline latency and cohort throughput, and cannot contend with another timed baseline request. The real connector's own durable effects remain inside its timer. Historical preliminary method-1 probes excluded bookkeeping from each individual timer but allowed it to contend with other samples; they are retained as diagnostic history, not the final reference. Monetary usage is zero for this local workload; electricity and hardware depreciation are not billed or estimated as provider cost.

The runner does not run external API calls. It never changes holdout labels or claims a target was met without the corresponding measured report.

The report hashes the actual runner's backend, benchmark script, worker source, runtime lock and selected model manifest before and after measurement. Changes during a run mark it failed. Acceptance also compares those exact hashes with the final source tree, so a later optimization or worker change requires a new measurement. Runtime source is mounted read-only only into the trusted test runner. The signed model and policy configuration bindings remain separate from these implementation hashes.

Acceptance requires every full-mode single-client cohort to complete its legal report, and records positive uncached guard token and slot usage. A matrix consisting only of fast rejections cannot certify semantic performance. Capacity rejections at ten or fifty concurrent clients remain visible separately.

For preliminary performance diagnosis, invoke `scripts/benchmark.py --focused-deterministic --repetitions 3` inside the trusted runner. It measures the two non-semantic modes at 4 KiB and ten clients, both cache variants and model-preparation labels: eight rows and 240 attempts. These are written only to `artifacts/benchmark-probe.json` and HTML. The acceptance aggregate still requires the separate complete 144-row benchmark.

An isolated GPU Compose project can run the complete matrix with `--environment-label isolated-gpu --hardware-report artifacts/gpu-preflight.json`. Use that project's Compose overrides and isolated policy/feeds mounts for the runner. The hardware report must identify the GPU profile; the runner rejects a CPU manifest under a GPU label. The exact signed model artifacts, semantic configuration and initial worker readiness are recorded. A GPU performance measurement does not replace reference CPU functional and offline-install proofs. Report other concurrent host workloads when interpreting results.
